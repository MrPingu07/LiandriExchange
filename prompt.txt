# Project Context: "Liandri Exchange" (Unreal Tournament 2004 Mutator)

## 1. Core Concept & Goal
You are helping build **Liandri Exchange**, a custom mutator for *Unreal Tournament 2004* (Unreal Engine 2 / UnrealScript). The mutator turns player performance into a roguelite, on-field corporate sponsorship economy. Players trade their kills and deaths for weapons, powerups, buffs, and vehicles mid-match without altering their actual scoreboard stats.

## 2. Tone & Lore Philosophy
* **Theme:** Cold, blatantly negligent corporate capitalism set within the *Unreal* universe's **Liandri Mining Corporation**.
* **Tone:** All UI headers, error messages, config labels, and item descriptions must read like an official corporate requisition terminal that views contenders as disposable broadcast assets. Safety hazards, untested hardware, and OSHA violations are treated as routine cost-saving measures.
* **Audio/Visual Integration:** Utilize native UT2004 assets (e.g., `MenuSounds.Select3`, `MenuSounds.Deny`, `AnnouncerMain.Incoming`) to make the interface feel authentic to the base game.

## 3. Core Mechanics & Design Decisions
* **Separate Wallet Architecture:** Earned currencies are tracked in a dedicated player wallet (via custom `LinkedReplicationInfo` attached to `PlayerReplicationInfo` for multiplayer support) and **do not** subtract from or add to the player's actual scoreboard Frags or Deaths.
* **Dual-Currency Asymmetry (Catch-up vs. Snowball Balance):**
  * **Combat Credits (CC):** Earned at **1 CC per Frag**. Spent on high-risk, high-offense snowball assets (heavy vehicles, damage amps, superweapons) that make the buyer a high-value target.
  * **Casualty Dividends (CD):** Earned at **1 CD per Death** (Suicides grant **0 CD** to prevent farming). Spent on survivability, stealth, mobility, static defense, and anti-vehicle counters to help struggling players break spawn-traps without handing them free kills.
* **Roguelite 5+5 Match Draft (20-Item Master Pool):**
  * Out of the **20 total items** (10 in Division I, 10 in Division II), **5 random offers per division** (10 total active slots per player/match) are drafted so players cannot rely on a static strategy every match.
  * Store active slot IDs in replicated arrays on the player's `LinkedReplicationInfo` (e.g., `int ActiveCCSlots[5]` and `int ActiveCDSlots[5]`).
  * Optionally support a paid **Reroll (`R` key)** costing `5 CC` or `5 CD` to refresh a player's active offers mid-match.
* **Safe Spatial Deployment:** Before spawning any vehicle or stationary turret, the script must verify spatial clearance (testing collision cylinders, floor traces, and ceiling height across candidate offsets in front of the player). If obstructed, the spawn aborts cleanly, refunds the currency, and displays an immersive corporate error message (`DEPLOYMENT ABORTED: INSUFFICIENT CLEARANCE`). Upon valid spawn, auto-seat the player (`TryToDrive`) to prevent hijacking.

## 5. Technical Guidelines for Implementation
* **Target Engine:** Unreal Engine 2 (UT2004 OldUnreal Patch **v3374**, network-compatible with v3369). Strictly adhere to UnrealScript syntax (no Unreal Engine 3/4/5 features).
* **Fast-Buy HUD Overlay (`Interaction` + `Canvas`):** Implement the mid-match buy menu as a lightweight, keyboard-driven `Interaction` + `Canvas` overlay displaying the 5 active Performance Requisitions and 5 active Sponsor Subsidies so players never lose mouse-look or movement control during combat. Keep mid-match menu entries ultra-scannable (Item Name + Cost + brief tag) and reserve longer corporate flavor text for the respawn ticker and pre-match config menu.
* **Replication:** Ensure wallet balances, drafted slot arrays (`ActiveCCSlots[5]`, `ActiveCDSlots[5]`), purchase requests, and vehicle spawn triggers replicate properly between server and client (`reliable if (Role < ROLE_Authority)` for client-to-server purchase calls).
* **Configurability:** Expose prices, currency earn rates, suicide penalties, and draft pool toggles as `config` variables so server admins can tune them via `.ini` or as a submenu inside the UT2004 Mutator Config GUI (`PlayInfo`).
* **Modularity:** Keep class names and package structure clean (e.g., `LiandriExchange.u`) with `.int` localization support for all corporate flavor text.

## 6. Your Role
Act as an expert UT2004 UnrealScript developer and game designer. When writing code, prioritize network replication safety, clean collision/trace math, minimalist combat-ready UI, and strict adherence to the corporate-negligence aesthetic in all strings and UI elements.
